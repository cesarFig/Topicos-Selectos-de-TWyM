Instrucciones: Responde de manera clara y concisa a cada una de las siguientes preguntas abiertas. El propósito de esta evaluación es medir tus conocimientos previos en Ingeniería de Software.

1. Metodologías: ¿Cuál es la diferencia principal entre una metodología de desarrollo tradicional (como Cascada) y una metodología ágil (como Scrum) frente a los cambios en los requisitos? 
En la metodologia agil es mas facil aplicar los cambios en los requisistos porque constantemente se estan realizando entregables, entonces no afecta tanto al proceso de desarollo como si estuvieramos en cascada.


2. Requerimientos: Explica la diferencia entre requerimientos funcionales y no funcionales, dando un ejemplo de cada uno aplicable a una plataforma web. 
Los requerimientos funcionales son los que estan directamente relacionados con la funcion principal del software, es decir, los que verdaderamente son necesarios para que cumpla su funcion, mientras que los no funcionales son los adicionales que en dado caso que no se realicen no afecta tanto a la pagina o la aplicacion. 
Un ejemplo de un requisito funcional podria ser que el usuario se pueda loguear y uno no funcional es que pueda cambiar su foto de perfil.

3. Arquitectura: Describe el modelo Cliente-Servidor y explica brevemente cómo se comunican el frontend y el backend en una aplicación web moderna. 
Es cuando el cliente solicita informacion mediante una solicitud y el servidor la procesa y le da una respuesta. Se comunican mediante peticiones GET, POST, UPDATE o DELETE utilizando algun protocolo.


4. Bases de Datos: ¿En qué escenarios recomendarías utilizar una base de datos relacional (SQL) frente a una no relacional (NoSQL) para el almacenamiento de datos en una aplicación? 
Recomendaria usar la base de datos relacional cuando la aplicacion no sea tan grande y no maneje tantos registros, en caso contrario, recomendaria la no relacional


5. APIs: ¿Qué es una API REST y qué papel fundamental juega en la integración entre una aplicación móvil y los servidores (backend)? 
Es una conjunto de reglas que comunica a dos sistemas. Juega un papel importante ya que comunica al front con el back para que puedan intercambiar informacion


6. Control de Versiones: Explica la importancia de utilizar Git en un equipo de desarrollo de software y describe brevemente qué es un "merge conflict" (conflicto de fusión). 
Es importante para evitar perder alguna version que si funcionaba cuando otra mas reciente no lo hace, ademas de tener una mejor organizacion en el equipo. Y un merge conflict es cuando en cierta linea de codigo se han realizado uno o varios cambios al mismo tiempo y git no sabe que cambio es el que debe de aplicar


7. Pruebas: ¿Qué son las pruebas unitarias (unit testing) y por qué son cruciales para asegurar la calidad del software antes de su paso a producción? 
Son aquellas que prueban las operaciones o funciones basicas de las cuales otras funciones dependen y son importantes porque garantizan un procentaje de funcionalidad del software


8. POO: Define los conceptos de encapsulamiento y polimorfismo de la Programación Orientada a Objetos, y menciona cómo ayudan a crear un código más mantenible. 
El polimorfismo es cuando una clase puede actuar de manera distinta a un mismo metodo y el encapsulamiento es controlar el acceso y proteger los atributos.

10. Seguridad: Explica la diferencia técnica entre "autenticación" y "autorización" en el contexto de seguridad de una aplicación. 
Autenticacion es cuando el usuario se loguea mediante credenciales y el sistema valida que sean correctos sus datos.
Autorizacion son los permisos que el sistema le da a un usuario autenticado para leer, modificaro o eliminar algun dato que desee
